# LMBenchmark Real Multi-Round QA 데이터 준비

상위 저장소: https://github.com/LMCache/LMBenchmark
확인한 커밋: c1e05a708a5a1fd04a9ec09d215edbdcccdf92cb
실행 대상: real-multi-round-qa (CxS). 합성 멀티턴이나 ShareGPT와는 다른 경로다.

## 데이터

원본 prepare.py와 같은 Gutenberg 텍스트 URL을 사용한다. book ID 1~800 순서에서
Qwen3-14B 토크나이저로 16,384토큰 이상인 책 200개를 확보하는 것이 준비 목표다.
책을 성능 결과에 따라 선택하지 않으며 원문·URL·해시·길이·제외 이유를 기록한다.
연속 다운로드는 직렬로 하고 요청 사이 1초 간격을 두며, 연결/5xx 오류만 제한 재시도한다.
403/429는 우회하지 않고 중단한다.
제한 재시도 후에도 연결할 수 없는 개별 책은 제외 이유를 기록하고 다음 ID로 진행한다.
연속 5개에서 연결 실패하면 다운로드 전체를 중단한다.

원본의 가장 큰 길이 구간 분류 대신, 모든 적격 책의 앞 16K 토큰을 사용하도록 변경했다.
이는 32K 모델 컨텍스트 안에 후속 대화와 출력을 남겨두려는 길이 제한이다.
실제 책의 발췌문이며 원문 전체 실행 또는 공식 기본 설정 그대로의 실행이라고 주장하지 않는다.
Gutenberg에는 소설 외의 자료도 있으므로 소설로만 구성된 데이터셋이라고 단정하지 않는다.

## 실험 초안 — 본 추론 실행은 아직 시작하지 않음

- Qwen3-14B, DRAM 캐시 256GiB, staging 8GiB.
- C=8, S=24, 총 192개 세션. 그룹별 세션을 턴마다 번갈아 실행하는 원본 CxS 방식을 유지한다.
- 원본과 같은 복원추출을 고정 seed로 한 번 수행해 세션-책 매핑을 저장한다.
- 초기 문서 수로 추정한 KV 총량과 실제 캐시 점유량은 다르다. 중복 문서·공유 prefix·캐시 입장/퇴출을 고려해야 한다.
- 실제 생성 답변을 다음 턴에 연결한다. 고정 입력 replay와는 다르다.
- 원본 `num_rounds`는 첫 요약 이후 후속 질문 횟수다. 총 요청 수를 정할 때 +1을 반영해야 한다.
- 프리페치 정책 선택과 데이터 준비가 끝난 뒤 입력 길이·메모리·DAOS 용량 안전 검증이 필요하다.

## 파일

- status.json: 다운로드 진행 상황. prepared는 데이터 준비 완료이지 벤치마크 완료가 아니다.
- documents.json: 적격 문서 목록과 해시.
- download_audit.json: 다운로드/길이/중복 검사 기록.
- raw/: Gutenberg 원문(라이선스 안내 포함).
- 16k/: 추론 입력에 사용할 16K 발췌문.
- sessions.json: 완료 시 생성하는 고정 세션 매핑.
- capacity_estimate.json: 완료 시 생성하는 고유 문서의 초기 KV 크기 추정.
