# EQ-Bench Longform 비교 실험

> 이 디렉터리는 실행기 검증용 1조건만 완료한 기록이다. OFF 계측 항목 집계 보완 및 검증 중 보조 테스트 실행 때문에 본 비교에서 제외했다. 본 36조건 결과는 `../eqbench_matrix_20260928_v2`에 저장한다. 원시 측정과 보완 후 집계는 모두 보존했다.

## 조건

- 모델: Qwen3-14B BF16, H100 NVL, 청크 128토큰, vLLM max-num-seqs 16.
- 동시 대화 8/16 × DRAM 8/4/2GiB × GPU staging 8/4GiB × off/wait/cancel = 36조건.
- 각 조건은 원본 첫 4개 주제를 4번씩 수행하는 총 16개 대화다. 대화당 계획 5단계 + 본문 8단계, 총 208회 모델 호출이다.
- 동시성 8에서는 먼저 8개 대화를 시작하고, 대화 하나가 끝나면 다음 대화가 시작한다. 후속 턴에 공통 장벽은 없다. 동시성 16에서는 16개 대화를 시작한다.
- 주제 반복 간에도 공통 prefix 캐시를 재사용할 수 있다. 대화별 고정 seed는 조건 간 동일하지만, 실제 출력이 다음 입력에 누적되므로 최종 입력·출력량의 동일성은 보장하지 않는다.

## 세 방식

|방식|DRAM 프리페치|조기 준비 알림|retrieve 시 대기 중 복사 취소|
|---|---|---|---|
|off|OFF|OFF|OFF|
|wait|ON|ON|OFF|
|cancel|ON|ON|ON|

wait/cancel은 **취소 여부만 다르다**. 이전 실험의 wait는 조기 준비 알림도 OFF였으므로 이름이 같아도 동일 조건이 아니다. 실행 중인 GPU 복사는 취소하지 않으며, 대기 중이던 복사가 취소되면 원래 DRAM 경로로 소비한다. DAOS 프리페치는 세 방식 모두 ON이다. DRAM 복사 작업자는 1개이고, staging 여유분을 임의로 예약하는 정책은 없다. 물리 용량 한계는 유지한다.

## 캐시와 저장 공간

조건마다 새 서버 프로세스·빈 DRAM·새 DAOS namespace로 시작한다. 조건 내부에서는 캐시를 유지하고 전체 warm 재실행은 하지 않는다. 스토리지 서버/운영체제 캐시까지 비운다는 뜻은 아니다.

조건이 완료되고 결과·그래프 저장을 확인한 뒤 해당 조건 namespace의 KV만 삭제한다. 전체 OID/컨테이너/풀을 삭제하지 않는다. `kv_cleanup`에 삭제 키 목록·실행 기록·기존 키 보존 검증을 남긴다. 삭제한 KV payload는 백업하지 않아 복구할 수 없지만, 입력·답변·계측 로그는 보존한다. 실패한 조건은 자동 삭제하지 않고 중단한다.

## 결과 확인

- [진행 상태](status.json): 현재 조건과 완료 목록. `completed`가 전체 완료를 뜻한다.
- [자동 갱신 표](RESULT_KO.md): 완료된 조건만 포함한다. 첫 조건이 끝난 뒤 생성된다.
- [전체 수치](summary.json), [CSV](summary.csv): 조건별 TTFT·전체 시간·hit·용량 부족 재계산·생성량.
- 각 조건의 `staging_hits.png`: 2초 구간별 staging 점유와 DRAM/DAOS hit. 점유율은 GPU 계산 사용률이 아니고, 첫 점은 시작 순간이 아니라 첫 2초 통계다.
- 각 조건의 `stories`: 실제 입력과 생성 답변, 요청별 TTFT/토큰 재사용.
- 각 조건의 `server`: 설정·명령·라이브러리 경로·서버 로그·계측 trace.

오류·공간 부족 시 다음 조건을 실행하지 않는다. 시간 제한으로 출력을 강제로 자르거나 EOS를 무시하지 않는다. 원본 설정의 출력 상한 4,000토큰은 유지하고 상한 종료 횟수를 기록한다. 공식 품질 채점 없이 생성 워크로드만 실행하며, 조건당 1회이므로 통계적 유의성 또는 순수 프리페치 인과효과를 단정하지 않는다.
