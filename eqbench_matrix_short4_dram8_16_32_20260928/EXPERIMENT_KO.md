# EQ-Bench Longform 축소본 — 새 36조건 실험

사용자 승인: 2026-09-28. 이전 8챕터 실험 결과는 보존하며 이 실험과 합산하지 않는다.

## 워크로드

- 모델: Qwen/Qwen3-14B BF16, thinking OFF, vLLM max-model-len 32768, max-num-seqs 16.
- 원본의 첫 4개 이야기 주제를 각각 4번 사용하여 총 16개 대화를 실행한다.
- 각 대화: 준비 5단계 + 본문 4챕터 = 9회 호출. 처음부터 4챕터를 계획하고 4장에서 완결한다.
- 호출당 최대 출력 2500토큰. EOS는 정상 적용하며 최소 출력 강제·패딩·대화 이력 절단은 하지 않는다.
- 본문 지시의 챕터당 약 1000단어는 유지한다. 출력 상한에 걸린 호출 수는 별도 집계한다.
- 조건당 144회, 전체 36조건 총 5184회 호출. 공식 전체 벤치마크나 품질 점수가 아닌 축소 성능 실험이다.
- 최초 동시 요청만 함께 시작하고 이후에는 각 대화가 응답을 받은 뒤 다음 단계를 진행한다. 완료된 대화 자리에는 다음 대화가 들어온다. 단계별 묶음 대기는 없다.

## 비교 조건

| 변수 | 값 |
|---|---|
| 동시 대화 | 8 / 16 |
| DRAM | 8 / 16 / 32 GiB |
| GPU staging | 4 / 8 GiB |
| DRAM 프리페치 | OFF / ON(wait) / ON(cancel) |

wait와 cancel은 early_ready ON으로 동일하며, retrieve 시 아직 시작하지 않은 DRAM 복사를 취소하는 설정만 다르다. DAOS 프리페치는 모든 조건에서 ON이다. DRAM 복사 작업자는 1개이고 임의의 점유율 제한 전략은 사용하지 않는다.

조건마다 새 vLLM 프로세스로 DRAM·staging을 비우고, 새 UUID DAOS namespace를 사용한다. 초기 계측의 CPU/GPU 사용량과 DAOS 쓰기가 0인지 확인한다. 조건 중에는 실제 대화와 반복 주제로 캐시가 자연스럽게 재사용된다. 조건 종료 후 해당 namespace의 키만 삭제하며 다른 데이터와 로그·그래프는 보존한다.

## 길이 검증

실제 Qwen 토크나이저로 각 단계의 지시문·채팅 형식과 빈 답변 이력을 계산하고, 모든 출력에 2500토큰 예산을 더했다. 최대 예상 예산은 23446토큰, 최소 잔여는 9322토큰으로 사전 여유 기준 4096토큰을 통과했다.

이는 답변 재토큰화까지 보장하는 수학적 상한은 아니다. 매 요청의 실제 입력을 재토큰화하여 `입력 + 2500 <= 32768`을 추가 확인하며, 초과하면 이력을 자르지 않고 실패를 기록한다. 상세 사전 검증은 실행 시 `context_preflight.json`에 저장된다.

## 결과와 실행 관리

- 진행: `status.json`, `supervision/heartbeat.json`
- 완료 조건 표: `RESULT_KO.md`, `summary.csv`
- 조건별: `summary.json`, `staging_hits.png`, 요청별 토큰·TTFT·hit 및 용량 부족 재계산 기록
- 서비스: `discos-minji-eqbench-short.service` (root 사용자 systemd 서비스)
- 일시적인 연결·실행기 중단은 조건별 제한 횟수 내 재시도한다. 불완전한 시도는 별도 보존하고 해당 KV를 정리한다. OOM·계측 오류 등은 무한 재시도하지 않고 조사 필요 상태로 남긴다.
- 조건별 1회 실행이다. 실제 생성 답변이 누적되므로 출력량·캐시 재사용량·새로 계산한 토큰 수가 조건별로 달라질 수 있으며 시간만으로 프리페치 효과를 단정하지 않는다.

검증: 시작 전 단위 테스트 193개 통과. 이전 중단 조건의 KV 4302개 삭제 확인, 나머지 54225개 키 보존 확인.
