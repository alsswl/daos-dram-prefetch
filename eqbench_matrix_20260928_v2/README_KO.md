# EQ-Bench Longform 본 비교

동시 대화 8/16 × DRAM 8/4/2GiB × GPU staging 8/4GiB × DRAM 프리페치 off/wait/cancel = **36조건**.

모델은 Qwen3-14B BF16, 청크 128토큰, vLLM max-num-seqs 16, DRAM 복사 작업자 1개다. DAOS 프리페치는 모든 조건에서 켜 둔다. wait/cancel은 모두 조기 준비 알림이 ON이며, retrieve 시 아직 시작하지 않은 DRAM 복사를 취소하는지 여부만 다르다. 이미 실행 중인 복사는 취소하지 않는다. 이전 wait(조기 준비 알림 OFF) 결과와 동일한 설정이 아니다.

첫4개 원본 이야기 주제를 각각4번 실행한다. 총16대화 × 대화당13단계 = 조건당208회, 전체7,488회 모델 호출이다. 각 대화는 실제 생성 답변을 다음 입력에 누적한다. 동시성8에서는 한 대화가 끝나면 다음 대화가 들어오며, 후속 턴에 공통 장벽은 없다. 반복 주제 간 캐시 재사용도 포함된다.

조건마다 새 프로세스·빈 DRAM·새 DAOS namespace로 시작한다. 전체 warm 재실행이나 중간 캐시 초기화는 없다. 서버/운영체제 캐시까지 비운다는 뜻은 아니다. 출력 상한4,000토큰, 정상 EOS, 원본 프롬프트를 유지한다. 출력 길이 강제, 입력 padding, 임의 복사 지연, staging 예약 한계는 추가하지 않았다. 공식 품질 채점은 하지 않는다.

## 진행과 결과

- [진행 상태](status.json): 현재 조건과 완료 목록.
- [자동 갱신 표](RESULT_KO.md), [CSV](summary.csv), [전체 수치](summary.json).
- 각 조건의 `staging_hits.png`: 2초 구간 staging 평균/최대와 조회 후보 청크 기준 DRAM/DAOS hit 비율.
- 각 조건의 `requests_summary.json`: 요청별 실제 재사용·재계산, 용량 부족 귀속 검증.
- 각 조건의 `stories`: 실제 요청·답변. `server`: 설정·명령·라이브러리·로그·계측.

완료된 조건은 결과·그래프를 저장하고 해당 namespace의 KV만 삭제한다. `kv_cleanup`에 삭제 목록·기존 키 보존 검증을 남긴다. 로그와 답변은 보존하지만 삭제한 KV는 백업하지 않는다. 실패한 조건은 다음 실행으로 넘어가지 않으며, 임의로 재시도하지 않는다.

실시간 생성으로 조건별 입력·출력량과 hit가 달라질 수 있다. TTFT와 함께 생성 토큰·새로 계산한 토큰·hit 비율을 해석해야 한다. 조건당1회라 통계적 유의성 또는 순수 인과효과를 단정할 수 없다.

직전 `eqbench_matrix_20260928`의 1조건은 실행기/정리 검증용으로 제외했다. 본 측정은 보완된 동일 소스를 사용하며, 실행 중 별도 단위 테스트나 다른 GPU 실험을 함께 실행하지 않는다.
